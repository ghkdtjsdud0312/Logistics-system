# Day 1 (금) — 기반 정리, 기준정보, 입고·재고

## 1. 오늘의 목표

문서를 확정하고 새 도메인 구조의 기반을 만든 뒤, 기준정보와 입고·적치·재고까지 동작하게 한다. 하루 종료 시 "입고 100개 적치 → 재고 현황 조회"가 API와 화면에서 재현되어야 한다.

## 2. 관련 범위

- 요구사항: `REQ-001`~`REQ-006`, `NFR-001`, `NFR-003`, `NFR-005`
- 작업: `TASK-001`~`TASK-004`
- 범위 밖: 주문, 피킹, 배차, Kafka Consumer, 대시보드

## 3. 세부 개발 내용

### 3.1 문서·계약 확정
- `.ai/` 개정본 승인, `API_SPEC.md`를 "확정"으로 변경(기준정보·입고·재고 부분 우선)

### 3.2 기반 정리 (TASK-001)
- 폐기 대상 코드(경로·후보·anomaly·outbound) 정리 계획 보고 후 승인받아 제거
- `global/event`에 상태 변경 이벤트 공통 발행 컴포넌트(AFTER_COMMIT) 추가. 도메인은 이 컴포넌트로 발행만 한다.
- 스키마 관리 방식 결정(`DECISION_LOG.md` 미결정 5번)

### 3.3 기준정보 (TASK-002)
- `master` 도메인: 상품, 창고·구역·위치, 차량·기사(기존 재사용, 컬럼 조정)
- 창고 트리 조회, 코드 중복 검증

### 3.4 입고·적치·재고 (TASK-003)
- `inbound`: 입고예정 → 입고완료 → 적치대기 → 적치완료
- `inventory`: 재고(상품+위치), 적치 시 증가, `가용 = 현재 - 예약`, 낙관적 잠금
- 재고 현황 검색(창고·구역·상품·재고상태)

### 3.5 프런트 (TASK-004)
- `AppLayout`(Header, Sidebar: 7개 메뉴), 라우팅, 상태 상수·타입 분리
- 기준정보 3화면, 재고 현황, 입고·적치 화면 (타입 `src/types/`, 상수 `src/constants/`, API `src/services/`)

## 4. 테스트와 검증

- 상품/위치 코드 중복 거부
- 입고 상태 전이(정상·금지), 적치 후 재고 증가, 재적치 거부
- 재고 불변식(음수 불가, 가용 계산)
- 백엔드 빌드·테스트, 프런트 빌드

## 5. 완료 기준

- [ ] 입고 100개 적치 후 재고 현황에 현재 100 / 예약 0 / 가용 100
- [ ] 입고 상태 전이가 규칙대로 동작하고 이벤트가 발행된다
- [ ] 테스트·빌드 통과, 인증 없이 접근 가능
- [ ] 모든 소스 파일이 크기 제약(약 30~50줄)을 지킨다(초과 시 사전 승인)
