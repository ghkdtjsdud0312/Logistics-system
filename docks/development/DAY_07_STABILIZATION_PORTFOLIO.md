## 7. 포트폴리오 설명 포인트

### 문제

물류 담당자는 출고 물량과 차량 제약을 함께 고려해 배차하고 배송 순서를 정해야 한다.

### 핵심 구현

- 완료 입고 수량 기반 출고 계획
- 중량·부피·가용성 기반 차량 후보
- 담당자 승인형 배차
- Nearest Neighbor + 2-opt 경로 개선
- 상태 머신과 비정상 처리
- Kafka 후속 처리, Redis 조회 캐시, SSE 관제

### 검증

- 도메인 경계·오류·동시성 테스트
- Consumer 멱등성
- Redis 적용 전후 k6 비교
- Docker Compose 재현

## 8. AI 하네스 기록

AI가 프로젝트를 대신 설계했다는 표현보다 다음을 증거로 남긴다.

- 요구사항 ID와 Task/테스트 추적
- 승인 게이트에 따른 범위 통제
- 구현 전 영향 범위 확인
- 자동 테스트와 빌드 피드백 루프
- ADR을 통한 설계 변경 기록

AI 생성 코드도 동일한 리뷰와 검증 기준을 통과했다는 점을 설명한다.

## 9. 한계와 확장 방향

- 좌표 기반 거리이므로 실제 도로 상황을 반영하지 않는다.
- 단일 차량 TSP 근사이며 다중 차량 VRP가 아니다.
- Outbox 미적용 시 DB 커밋과 이벤트 발행 사이 실패 가능성이 있다.
- 인증·권한과 개인정보 보호는 운영 수준이 아니다.
- 로컬 k6 결과를 실제 운영 성능으로 일반화할 수 없다.

확장 방향은 지도 행렬, 시간창 VRP, Outbox/CDC, 실제 관측성 순으로 제시할 수 있으나 현재 완료 기능과 구분한다.
