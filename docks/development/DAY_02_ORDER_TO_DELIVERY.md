# Day 2 (토) — 주문부터 배송까지 (`ORD-001` 관통)

## 1. 오늘의 목표

주문 하나가 주문접수에서 배송완료(또는 배송실패)까지 이동하는 핵심 흐름을 완성한다. 종료 시 `DEMO_SCENARIO.md`의 1~10단계가 API와 화면에서 재현되어야 한다.

## 2. 관련 범위

- 요구사항: `REQ-007`~`REQ-020`, `NFR-002`, `NFR-006`
- 작업: `TASK-005`~`TASK-009`
- 범위 밖: 반품 흐름 처리(실패 시 반품 생성 호출 지점만 준비), 감사로그 조회, 대시보드

## 3. 세부 개발 내용

### 3.1 주문·재고 예약 (TASK-005)
- 주문 생성: 위치별 예약, 부족 시 `INSUFFICIENT_STOCK`. 목록 검색과 상세(타임라인·수량·배송정보)
- 출고 지시: 피킹 작업 생성, 주문 `OUTBOUND_WAITING`
- 주문 상태 전이 메서드는 `order` 도메인만 소유한다(ADR-011)

### 3.2 피킹·포장 (TASK-006)
- 피킹 시작/완료(수량 일치 검증, 현재·예약 동시 차감), 모든 작업 완료 시 포장 작업 생성
- 포장 완료(박스 코드)

### 3.3 상차·배차 (TASK-007)
- 포장완료 주문 상차 → 주문별 Shipment 생성
- 배차 등록(차량·기사·시각·Shipment): 적재량(kg)·가용·중복 배정 검증, 실패 시 부분 데이터 없음
- 배송 시작(차량·기사 운행중, 주문 배송중), 배송 시작 전 취소

### 3.4 배송현황·완료·실패 (TASK-008)
- 차량별 진행률과 주문별 상태 조회
- 배송 완료(인도수량 일치), 배송 실패(사유·상세, 반품 생성 훅)
- 모든 Shipment 종결 시 배차 완료, 차량·기사 복귀

### 3.5 프런트 (TASK-009)
- 주문 목록/상세, 피킹·포장 탭, 상차·배차·배송현황·완료·실패 화면
- 상태 Badge와 한글 매핑은 `src/constants/`, 진행 타임라인은 재사용 컴포넌트

## 4. 테스트와 검증

- 재고 예약 성공/부족/동시 주문, 피킹 수량 불일치, 재고 차감 정합성
- 적재량 경계값, 이중 배정, 배차 실패 롤백, 배차 취소 원복
- 인도수량 불일치, 배차 자동 완료
- `ORD-001` E2E 서비스 테스트 (주문 → 배송완료)

## 5. 완료 기준

- [ ] `ORD-001` 흐름이 화면과 API에서 끝까지 동작하고 수량이 `10/10/10/10/10`으로 일치한다
- [ ] 재고: 예약 시 가용 감소, 피킹 시 현재 감소, 음수 없음
- [ ] 금지 전이가 오류 코드로 거부된다
- [ ] 테스트·빌드 통과, 파일 크기 제약 준수

## 6. 다음 단계 인계

Day 3의 반품은 배송 실패 훅에서 시작하고, 감사로그와 대시보드는 오늘 발행한 상태 변경 이벤트를 소비한다. 이벤트 누락 지점이 없는지 시작 전에 점검한다.
