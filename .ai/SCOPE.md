# SCOPE

## Must Have

- 입고 등록, 검수 완료, 입고 완료
- 입고 완료 재고를 대상으로 한 출고 계획
- 차량/기사 기본 정보와 운행 가능 상태
- 중량·부피 기반 배차 가능성 검증
- 배차 생성과 담당자 확정
- 좌표 기반 배송 순서 계산 및 전후 거리 비교
- 상차 완료, 배송 시작, 경유지 완료, 배송 완료 상태 관리
- 배송 이력과 이상 기록
- Kafka 이벤트, Redis 조회 캐시, SSE 관제 이벤트
- 핵심 API와 도메인 규칙 테스트
- Docker Compose와 k6 결과

## Should Have

- 배차 추천 후보를 적합도 순으로 반환
- 차량 과적, 기사 중복 배차, 잘못된 상태 전이 탐지
- 대시보드 요약 및 실시간 이벤트 피드
- 샘플 데이터 시드와 데모 시나리오

## 제외 범위

- 실제 재고 원가·회계·WMS 전체 기능
- 실시간 GPS 수집과 실제 내비게이션
- 교통량·통행료·도로 제한을 반영한 실제 도로 최적화
- 주문 결제, 회원가입, OAuth, 복잡한 권한 체계
- 다중 물류센터 간 네트워크 최적화
- 분할 배송, 냉장/위험물/혼적 금지 등 고급 제약
- MSA, Kubernetes, Service Mesh
- AI/ML 예측 모델

## 단순화 가정

- 물량 하나는 한 배차에만 속하며 분할하지 않는다.
- 배송지는 위도·경도 대신 데모용 평면 좌표 `(x, y)`를 사용할 수 있다.
- 거리와 예상 시간은 실제 도로값이 아닌 프로젝트 거리 모델의 결과다.
- 기사 한 명은 같은 시간 구간에 한 배차만 담당한다.
- 경로 최적화는 단일 차량별 TSP 근사 문제로 제한한다.

## 시간 부족 시 축소 순서

1. 프론트 화면을 5개에서 3개로 축소
2. 배차 자동 확정 대신 추천 + 담당자 확정 유지
3. Kafka Consumer를 이력/이상 두 개로 제한
4. Redis 캐시 대상을 배송/배차 상세 한 종류로 제한

경로 최적화, 상태 전이, 배차 제약, 테스트는 축소하지 않는다.
