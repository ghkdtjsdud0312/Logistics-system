# 7-DAY DEVELOPMENT PHASES

하루 종료 시 반드시 실행 가능한 상태와 데모 증거를 남긴다. 다음 날 기능을 미리 당겨 범위를 넓히지 않는다.

## Day 1 — 계약과 실행 기반

- Spring Boot/React 기본 구조
- PostgreSQL, Flyway, Docker Compose
- 공통 오류 응답과 추적 ID
- 핵심 Entity 초안 및 마이그레이션
- OpenAPI/health check

종료 증거: 애플리케이션 실행, DB 마이그레이션, health PASS.

## Day 2 — 입고와 출고 계획

- 입고 등록·검수·완료
- 출고 계획 생성
- 가용 수량 검증
- API/서비스/Repository 테스트

종료 증거: 입고부터 출고 READY까지 API 시연.

## Day 3 — 차량·기사·배차

- 차량/기사 샘플 데이터
- 후보 차량 조회와 제외 사유
- 적재량 및 일정 충돌 검증
- 배차 확정과 동시성 테스트

종료 증거: 적합 차량 추천, 과적/중복 배차 거부.

## Day 4 — 경로와 배송 상태

- 거리 계산, Nearest Neighbor, 2-opt
- 경로 저장과 개선율 응답
- Dispatch/Stop 상태 머신
- 배송 이력

종료 증거: 동일 좌표의 최적화 전후 거리와 상태 전이 테스트.

## Day 5 — Kafka·Redis·SSE

- 상태 이벤트 발행
- 이력/이상 Consumer와 멱등 처리
- 상세 조회 cache-aside와 무효화
- SSE 이벤트 스트림

종료 증거: 상태 변경 한 번으로 이벤트, 이력, 캐시 무효화, SSE 수신 확인.

## Day 6 — 운영 화면·통합·성능

- 대시보드, 입출고, 배차, 경로/관제 화면
- 대표 E2E 시나리오
- k6 캐시 OFF/ON 비교
- Docker Compose 전체 구동

종료 증거: 화면 시연과 성능 결과 파일.

## Day 7 — 안정화와 포트폴리오

- 버그 수정과 전체 테스트
- 아키텍처/ERD/시퀀스 다이어그램
- README 실행·데모·한계·의사결정
- API 예시, 성능 표, 화면 캡처
- 3~5분 데모 스크립트

새 기능은 추가하지 않는다.

## 중단 기준

각 Day의 필수 증거가 없으면 다음 기술을 추가하지 않는다. Kafka가 Day 5까지 불안정하면 먼저 동기 업무 흐름과 테스트를 보존하고, 실패 원인과 미완료 범위를 명시한다.
