# REQUIREMENTS

## 화면 구조 (메뉴)

```text
대시보드
주문관리   : 주문 목록 / 주문 상세
창고관리   : 재고 현황 / 입고·적치 / 피킹·포장
배송관리   : 상차관리 / 배차관리 / 배송현황 / 배송완료·실패
반품관리
스케줄   : 배차 일정·입고 예정 월간 달력
감사로그
기준정보   : 상품관리 / 창고·위치관리 / 차량·기사관리
```

## 핵심 업무 흐름 (End-to-End)

주문 생성 → 재고 확인(예약) → 출고 지시 → 피킹 → 포장 → 상차 → 배차 → 배송 → 배송완료 | 배송실패 → 반품

## 기준정보

- `REQ-001` 상품(코드, 이름, 단위, 단위 중량 kg, 사용 여부)을 등록·조회한다.
- `REQ-002` 창고 → 구역 → 위치(`A-01-01`) 계층을 등록하고 트리로 조회한다.
- `REQ-003` 차량(번호, 종류, 적재량 kg, 상태)과 기사(ID, 이름, 연락처, 상태)를 등록·조회한다.

## 입고·재고

- `REQ-004` 입고(입고번호, 거래처, 상품, 수량)를 예정 등록하고 `입고예정 → 입고완료 → 적치대기 → 적치완료`로 진행한다.
- `REQ-005` 적치완료 시 지정 위치(1곳)의 현재재고가 입고수량만큼 증가한다.
- `REQ-006` 재고 현황은 창고·구역·상품·재고상태로 검색하며 현재/예약/가용재고를 표시한다. `가용 = 현재 - 예약`.

## 주문

- `REQ-007` 주문(고객명·주소·연락처·상품 행)을 생성하면 위치별로 재고를 예약한다. 가용재고가 부족하면 주문을 거절한다.
- `REQ-008` 주문 목록을 주문번호·고객명·상태·주문일자로 검색하고 상태 Badge를 표시한다.
- `REQ-009` 주문 상세는 주문 정보, 상품별 수량(주문/피킹/상차/배송), 진행 타임라인, 배송 정보, 이벤트 이력을 보여 준다.
- `REQ-010` 주문 상태는 `주문접수 → 출고대기 → 피킹중 → 피킹완료 → 포장완료 → 상차완료 → 배차완료 → 배송중 → 배송완료 | 배송실패` 순서만 허용한다.

## 피킹·포장

- `REQ-011` 출고 지시 시 예약 위치별 피킹 작업이 생성된다.
- `REQ-012` 피킹 완료는 피킹수량이 요청수량과 같을 때만 가능하며 요청수량 초과는 금지한다. 완료 시 현재재고와 예약재고가 함께 차감된다.
- `REQ-013` 주문의 모든 피킹 작업이 끝나면 포장 작업이 생성되고, 박스 코드를 입력해 포장을 완료한다.

## 상차·배차

- `REQ-014` 포장완료 주문을 선택해 상차를 완료하면 주문별 Shipment가 생성된다.
- `REQ-015` 배차 등록은 상차 완료 Shipment, 차량, 기사, 출발/배송 예정 시각을 연결한다. 총 중량이 차량 적재량을 넘거나 차량·기사가 활성 배차 중이면 거부한다.
- `REQ-016` 배송 시작 시 배차 내 모든 주문이 배송중이 되고 차량·기사가 운행중 상태가 된다.
- `REQ-017` 배송현황은 차량별 진행률(완료/전체)과 주문별 배송 상태를 보여 준다.

## 배송 완료·실패

- `REQ-018` 배송 완료는 인도수량이 배송수량과 같을 때만 가능하다.
- `REQ-019` 배송 실패는 사유(고객 부재, 주소 오류, 수취 거부, 상품 파손, 기타)와 상세 내용을 기록한다.
- `REQ-020` 배차 내 모든 Shipment가 종결되면 배차가 완료되고 차량·기사가 운행가능으로 복귀한다.

## 반품

- `REQ-021` 배송 실패 시 반품이 자동 생성되며 `회수요청 → 회수중 → 회수완료 → 반품입고 → 처리완료`로 진행한다.
- `REQ-022` 반품입고 시 사유가 상품 파손이 아니면 지정 위치의 현재재고를 복구하고, 파손이면 복구하지 않는다.

## 감사로그·대시보드

- `REQ-023` 모든 상태 변경은 시간·사용자·대상·작업·이전상태·변경상태로 감사로그에 남고, 기간·사용자·대상·작업으로 검색한다.
- `REQ-024` 대시보드는 오늘의 주문·피킹대기·포장대기·상차대기·배송중·배송완료·배송실패 수, 단계별 진행 현황, 차량 배송 현황, 최근 이벤트를 보여 준다.
- `REQ-025` 대시보드는 SSE로 상태 변경을 실시간 반영한다.

## 스케줄·상세 화면·실시간 (추가)

- `REQ-026` 스케줄 화면은 배차 일정(출발~도착 예정 시각)과 입고 예정일을 월간 달력으로 보여 주고, 종류별로 표시를 켜고 끌 수 있으며, 항목을 누르면 관련 화면으로 이동한다. 기존 조회 API(`GET /dispatches`, `GET /inbounds`)를 사용한다.
- `REQ-027` 입고와 반품은 목록 외에 상세 화면(정보, 진행 단계, 단계별 처리)을 가진다. 기존 상세 API(`GET /inbounds/{id}`, `GET /returns/{id}`)를 사용한다.
- `REQ-028` 배송현황, 배송완료·실패, 스케줄, 입고·반품 상세 화면은 상태 변경 SSE 이벤트가 오면 자동으로 다시 조회한다.

## 비기능 요구사항

- `NFR-001` 로그인 없이 접근 가능하다(PermitAll).
- `NFR-002` 상태 변경 경로는 도메인 메서드로만 수행하며 금지 전이는 오류 코드로 거부한다.
- `NFR-003` Kafka 소비자는 멱등하다(중복 이벤트로 감사로그가 중복되지 않는다).
- `NFR-004` Redis 장애 시에도 PostgreSQL 조회로 기능을 유지한다.
- `NFR-005` Docker Compose로 PostgreSQL, Redis, Kafka를 로컬에서 재현한다.
- `NFR-006` 재고 갱신은 동시 요청에도 음수가 되지 않는다(낙관적 잠금).
