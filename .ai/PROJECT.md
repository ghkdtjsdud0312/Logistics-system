# PROJECT

## 프로젝트명

물류 통합 관리 시스템  
영문: Integrated Logistics Management System

## 목적

주문이 생성된 이후 창고의 재고 확인, 피킹, 포장, 상차, 배차, 배송, 배송 완료/실패, 반품까지의 전체 물류 프로세스를 하나의 시스템에서 관리하고 상태와 수량을 추적한다.

> **주문 → 창고 작업 → 차량 인수 → 배송 → 고객 인도**

## 핵심 흐름

```text
상품/창고/차량/기사 등록 → 입고·적치 → 재고 확보 → 주문 생성 → 피킹 → 포장
→ 상차 → 배차 → 배송중 → 배송완료 | 배송실패 → 반품/회수
```

`ORD-001` 주문 하나가 위 흐름 전체를 관통하는 것이 프로젝트의 핵심 증거다. 모든 상태 변경은 감사로그를 남기고 대시보드에 반영된다.

## 대상 사용자

- 물류 운영 담당자: 주문, 재고, 기준정보 관리
- 창고 작업자: 입고·적치, 피킹, 포장, 상차
- 배차·배송 담당자: 배차 등록, 배송 진행/완료/실패 처리
- 관제 담당자: 대시보드, 감사로그 확인

## 핵심 개발 기조

- 취업 포트폴리오 목적의 개인 프로젝트이며, 핵심 비즈니스 로직(재고 예약, 상태 전이, 수량 정합성)의 무결성과 인프라(Kafka, Redis, SSE) 활용 능력 입증에 집중한다.
- 로그인/인증 없이 모든 기능을 프리패스로 개발한다. 감사로그의 사용자는 `X-Actor` 헤더로 받는다.
- 핵심 업무 로직을 먼저 완성하고, 3D 창고·지도·달력 같은 시각화는 후순위로 둔다.

## 핵심 포트폴리오 증거

- `ORD-001` 하나가 주문부터 고객 인도까지 관통하는 E2E 시나리오
- 현재/예약/가용 재고 분리와 수량 정합성 (`가용재고 = 현재재고 - 예약재고`)
- 상태 머신 기반 도메인 모델링과 상태 변경 감사로그
- Kafka 기반 후속 처리 분리(감사로그, 대시보드)
- Redis 캐시 (대시보드 요약)
- SSE 실시간 대시보드

## 기술 스택

- Backend: Java 17, Spring Boot 3.x, Spring Data JPA, Bean Validation
- Database: PostgreSQL
- Cache: Redis / Event: Apache Kafka / Realtime: SSE
- Frontend: React, TypeScript, Vite, Tailwind CSS
- Test: JUnit 5 (테스트 DB는 기존 H2 관행 유지), Vitest
- Runtime: Docker Compose / API Docs: OpenAPI(Swagger)
