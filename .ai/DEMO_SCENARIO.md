# DEMO SCENARIO — ORD-001

주문 하나가 시스템 전체를 관통하는 시연 시나리오. 데이터: 상품 `WATER001 생수 500ml`, 위치 `A-01-01`, 차량 `12가1234`(1톤), 기사 `홍길동`.

**준비**: 빈 DB에서 백엔드를 띄운 뒤 `./scripts/demo-seed.sh`를 실행하면 1~2단계의 기준정보와 입고·적치(생수·라면·음료 각 100개)가 만들어진다. 대시보드를 다른 창에 열어 두면 단계마다 SSE로 갱신되는 것을 볼 수 있다.

| 순서 | 메뉴 | 동작 | 주문 상태 / 재고 변화 |
|---:|---|---|---|
| 1 | 기준정보 | 상품·위치·차량·기사 등록 | - |
| 2 | 창고관리 > 입고·적치 | `IN-001` 생수 100 입고완료 → A-01-01 적치 | 현재 100 / 예약 0 / 가용 100 |
| 3 | 주문관리 | `ORD-001` 생성 (김철수, 생수 10) | 주문접수 / 예약 10 / 가용 90 |
| 4 | 주문관리 > 주문 상세 | 출고 지시 버튼 (피킹 작업 `PICK-001` 생성) | 출고대기 |
| 5 | 창고관리 > 피킹·포장 | 피킹 시작 → 10개 피킹완료 | 피킹중 → 피킹완료 / 현재 90, 예약 0 |
| 6 | 창고관리 > 피킹·포장 | `PACK-001` 박스 `BOX-001` 포장완료 | 포장완료 |
| 7 | 배송관리 > 상차관리 | ORD-001 선택 후 상차완료 (Shipment 생성) | 상차완료 |
| 8 | 배송관리 > 배차관리 | `DSP-001` 12가1234 / 홍길동 / 13:00 등록 | 배차완료 |
| 9 | 배송관리 > 배차관리 | 배송 시작 | 배송중 |
| 10 | 배송관리 > 배송완료·실패 | 배송수량 10 = 인도수량 10 배송완료 | 배송완료 |
| 11 | 주문관리 > 주문 상세 | 최종 상태와 타임라인 확인 | 수량 10/10/10/10/10 |
| 12 | 감사로그 | 대상 `ORD-001`로 검색해 상태 변경 이력과 사용자(X-Actor) 확인, 주문 상세의 이벤트 이력·타임라인 시각도 같은 로그 | - |
| 13 | 대시보드 | 배송중 −1, 완료 +1, 최근 이벤트 추가가 SSE로 반영 | - |

## 실패 시나리오

`ORD-003`을 배송실패(고객 부재) 처리 → 반품 `RTN-001` 자동 생성 → 회수요청 → 회수중 → 회수완료 → 반품입고(위치 지정, 재고 복구) → 처리완료. 사유가 상품 파손이면 재고를 복구하지 않는다.
