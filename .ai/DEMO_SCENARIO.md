# DEMO SCENARIO

## 대표 시나리오

1. A사 입고 예정 3건을 등록한다.
2. 검수 후 2건을 완료하고 1건은 수량 불일치 상태로 둔다.
3. 완료 물량으로 서울 서부권 배송지 6개의 출고 계획을 만든다.
4. 차량 후보 API가 1톤 차량은 중량 부족으로 제외하고 2.5톤 차량을 추천한다.
5. 이미 배차된 기사를 선택하면 충돌 오류가 발생한다.
6. 가용 기사를 선택해 배차를 확정한다.
7. 초기 경로와 2-opt 개선 경로의 총 거리·개선율을 비교한다.
8. 상차 완료 후 배송을 시작한다.
9. 경유지 완료 이벤트가 SSE 관제 화면에 반영된다.
10. 금지 상태 전이를 요청해 오류와 이상 기록을 확인한다.
11. 동일 이벤트를 재전송해 이력이 중복되지 않음을 확인한다.
12. Redis OFF/ON k6 결과를 비교한다.

## 3분 발표 흐름

- 0:00~0:30 문제와 사용자: 물류 담당자의 출고·배차 의사결정
- 0:30~1:20 입고→출고→후보 추천→배차 시연
- 1:20~2:00 경로 최적화와 거리 개선
- 2:00~2:30 Kafka/SSE 이상 관제
- 2:30~3:00 테스트, Redis/k6 결과, 한계와 다음 단계

## 과장하지 않을 내용

- 실제 도로 최적 경로라고 표현하지 않는다.
- 산업용 WMS/TMS 전체를 대체한다고 표현하지 않는다.
- 로컬 k6 결과를 운영 환경 성능으로 일반화하지 않는다.
- AI가 작성한 코드를 검증 없이 사용했다고 말하지 않는다.
